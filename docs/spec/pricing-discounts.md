# Специфікація: Pricing Discounts

**Статус:** agreed
**Джерело:** `materials/feature-request.md`
**Автор рішень:** Pavlo Yeremenko

---

## 1. Мета

Створити детермінований рушій розрахунку знижок (tier та coupons) при оформленні замовлення, щоб клієнти могли прогнозовано користуватися знижками без втрат на копійках і щоб сума до сплати ніколи не ставала відʼємною.

## 2. Поза скоупом

- Зміни у вартості доставки.
- Знижки на доставку.
- Відображення помилок користувачу щодо невалідних чи прострочених купонів (ці ситуації обробляються мовчки/тихою відмовою).
- Додавання нових категорій чи рівнів.

## 3. Рішення щодо неоднозначностей

| # | Питання | Рішення | Чому саме так |
|---|---|---|---|
| D-1 | Промокод і рівень складаються чи застосовуються послідовно? | Послідовно: спершу рівень (tier), потім від залишеної суми застосовуються промокоди. | Так знижка ніколи не перевищить очікувану (уникаємо безкоштовних замовлень при 100% сумарній знижці). |
| D-2 | База знижки — товари чи товари + доставка? | Тільки товари (subtotal). Доставка не входить у базу знижки. | Доставка — це витрати третіх осіб (логістика). |
| D-3 | Кілька промокодів — усі / найвигідніший / перший? | Усі діючі промокоди застосовуються послідовно (в порядку введення). | Найпростіша та найбільш зрозуміла логіка для клієнта. |
| D-4 | Округлення: де і в який бік? | Округлення до найближчої цілої копійки (`Math.round`) після кожної окремої знижки. | Округлення на кожному кроці робить кожну знижку самостійною. |
| D-5 | Промокод на категорію рахується від чого? | Від оригінальної суми товарів відповідної категорії. | Рахувати від оригінальної вартості категорії простіше і не вимагає трекінгу ціни кожного товару через всі кроки знижок. |
| D-6 | `minSubtotalKopecks` перевіряється до чи після інших знижок? | До будь-яких знижок (за оригінальним subtotal). | Заохочує клієнтів додавати товари до кошика. |
| D-7 | Чи може підсумок стати відʼємним? | Ні, підсумок товарів обмежується знизу нулем (0). | Ми не платимо клієнтам за те, що вони забирають товар. |
| D-8 | Прострочений промокод — тиха відмова чи помилка? | Тиха відмова: промокод просто ігнорується, сума знижки = 0. | Не блокує checkout, просто не дає знижку. |

## 4. Критерії приймання

- **AC-1:** КОЛИ замовлення на 1 000 грн (100000 копійок) від Gold-клієнта (10%) без промокодів, ТОДІ знижка 100 грн (10000 копійок), сума товарів 900 грн (90000 копійок) + доставка.
- **AC-2:** КОЛИ промокод прострочений, ТОДІ він ігнорується (знижка за нього = 0), а застосовуються інші валідні знижки.
- **AC-3:** КОЛИ введено два промокоди (наприклад, 10% на все і 50 грн), ТОДІ вони застосовуються послідовно до залишкової суми. (сума 1000 грн -> 900 грн після 10% -> 850 грн після 50 грн).
- **AC-4:** КОЛИ знижка перевищує суму замовлення (фіксований купон на 1000 грн при сумі 500 грн), ТОДІ сума товарів дорівнює 0, підсумок не може бути від'ємним. (Граничний).
- **AC-5:** КОЛИ замовлення порожнє (сума 0), ТОДІ знижка 0 і результат 0. (Граничний).
- **AC-6:** КОЛИ знижка на рівень дає пів копійки (наприклад, 5% від 10010 копійок = 500.5), ТОДІ округлюється до 501 копійки (`Math.round`). (Граничний).
- **AC-7:** КОЛИ введено промокод із `minSubtotalKopecks` 100000 і початкова сума 100000, він застосовується, навіть якщо після знижки за рівень сума стала меншою.
- **AC-8:** КОЛИ введено промокод на категорію (напр. "digital", 20%) і в замовленні є "digital" на 500 грн та "standard" на 500 грн, ТОДІ знижка становить 100 грн (20% від 500 грн), і загальний total (subtotal - discount) > 0.

## 5. Контракт

```ts
import type { Order, Coupon } from "./types.js";

export interface PriceBreakdown {
  subtotalKopecks: number;
  tierDiscountKopecks: number;
  couponDiscountKopecks: number;
  shippingKopecks: number;
  totalKopecks: number;
}

export function priceOrder(order: Order, coupons: Coupon[]): PriceBreakdown;
```
