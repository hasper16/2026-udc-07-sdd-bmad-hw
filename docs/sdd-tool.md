# SDD Tool

Я використав інструмент **OpenSpec** (`@fission-ai/openspec`).

Що він згенерував:
- Ініціалізував папку `.agents/` (зі skills) та конфігурацію в `openspec/`.
- Створив структуру директорій `openspec/changes/pricing-discounts/` для нашого change (завдяки `openspec new change`).
- Згенерував шаблони та інструкції для `proposal.md`, `specs/.../spec.md`, `design.md`, `tasks.md`.

Що він дав понад звичайну markdown-специфікацію:
- Строгий процес (workflow), де кожний наступний крок (specs, design, tasks) перевіряється, і наступні кроки заблоковані, поки не завершено попередній.
- Явні інструкції для кожного кроку (вміщують перевірку якості та вимоги до форматування), які не дають пропустити важливі речі, як-от ризики чи архітектурні рішення в design.md.
- Валідацію синтаксису (наприклад, перевірка `#` для сценаріїв).

Що довелося робити руками:
- Власне писати логіку (AC, рішення) у ці файли, базуючись на `feature-request.md`. Інструмент створює каркас і дає інструкції, але думати над бізнес-логікою все одно має людина (чи LLM).
